01 · Problem

Problem

Application security teams and service builders lose days triaging unreachable static scanner alerts, conducting manual launch threat reviews, and reviewing AI-suggested patches that break production behavior.

AppSec & Cloud Posture

Overview

SecPosture automates service posture assessment and remediation across application code and AWS identity boundaries. Its AST analyzer parses Python services in 0.509 ms median, traces public HTTP routes and lambda_handler entrypoints across helper calls, and filters out 44.4% (8 / 18) of dead-code alerts while keeping 100.0% recall (10 / 10) on live exploitable paths. Its graph solver maps multi-hop AWS IAM escalations (iam:PassRole, sts:AssumeRole, wildcard s3:GetObject) alongside stateful CloudTrail kill-chain telemetry. Finally, its closed-loop patcher writes minimal code fixes into an isolated /tmp sandbox, re-runs the AST scanner to confirm 0 reachable flaws remain, and runs unittest (12 / 12 runs verified, 16 / 16 service tests passing) before marking any patch ready for code review.

01 · ALERT FATIGUE

Dead-Code Findings Bury Real Risks

Pattern-only scanners treat an uncalled legacy migration helper identically to a public checkout endpoint, forcing engineers to chase harmless findings while live SQL injection or SSRF paths wait in queues.

02 · COMPOUND PATHS

Code & IAM Are Reviewed in Silos

An outbound URL bug looks moderate alone until combined with an execution role holding iam:PassRole and lambda:UpdateFunctionCode over an admin role that reads customer KYC buckets.

03 · UNVERIFIED FIXES

Raw LLM Patches Break Service Behavior

Asking a language model to rewrite a vulnerable module often alters unrelated helpers, introduces syntax errors, or breaks callers unless a deterministic test harness gates every diff.

04 · SINGLE-EVENT SIEM NOISE

Isolated Log Rules Miss Kill Chains

Alerting on every single AccessDenied or AssumeRole floods on-call responders, whereas real intrusions progress through reconnaissance, credential access, lateral movement, and bulk data reads.

03 · Implementation

Implementation

Five backend modules implement AST call-graph reachability, multi-hop IAM pathfinding and CloudTrail sequence correlation, closed-loop test-verified patching, Bedrock STRIDE reviews, and serverless API routing.

12 / 12 Unit Tests Passing
01 · AST TAINT & CALL-GRAPH REACHABILITY secposture/reachability_ast.py
Instead of flagging every regex match in a repository, SecPosture builds the function call graph starting from public HTTP routes (@route) and event handlers (lambda_handler), proving which sinks can actually be reached by external requests.
ReachabilityASTScanner.scan_source() parses Python code via ast.parse() in 0.509 ms median, propagates parameter taint across local assignments and helper calls, detects five CWE classes (CWE-89 SQLi, CWE-78 command injection, CWE-918 SSRF, CWE-502 pickle deserialization, and CWE-798 hardcoded secrets), and separates REACHABLE_EXPLOITABLE paths from UNREACHABLE_DEAD_CODE helpers.
02 · IAM ATTACK-PATH GRAPH & KILL-CHAIN ENGINE secposture/attack_graph.py
SecPosture combines proactive cloud posture graph solving with active CloudTrail telemetry detection so security teams can eliminate toxic role chains before launch and catch multi-stage intrusions in flight.
analyze_iam_attack_paths() runs Dijkstra over IAM role edges (iam:PassRole + lambda:UpdateFunctionCode, unconditioned sts:AssumeRole, iam:AttachRolePolicy, wildcard s3:GetObject / kms:Decrypt) in 0.021 ms median and synthesizes least-privilege policies that cut crown-jewel paths from 4 to 0. detect_cloudtrail_kill_chain() correlates 4 stages in 0.006 ms median with 100.0% precision and recall across 16 traces.
03 · CLOSED-LOOP AUTO-PATCH & /TMP TEST GATE secposture/autopatch_loop.py
Every generated code fix is scoped strictly to reachable functions, leaving uncalled legacy helpers untouched to keep diffs small, and must pass static re-scanning plus the service's behavioral unit tests before review.
run_closed_loop_autopatch() rewrites interpolated SQL into ? parameter tuples, converts shell=True calls to shell=False argv lists with metacharacter guards, inserts _validate_https_allowlist() blocking RFC1918 and 169.254.169.254, swaps pickle.loads for json.loads, re-scans the AST (10 -> 0 reachable flaws), and runs python3 -m unittest in /tmp (67.01 ms median).
04 · BEDROCK STRIDE REVIEWER & AUDIT LEDGER secposture/threat_review.py · server.py
Launch threat reviews ground Amazon Bedrock directly in deterministic AST line spans and IAM role ARNs, preventing hallucinated findings and recording every review and patch receipt in an append-only SQLite hash chain.
generate_appsec_threat_review() compiles a 6-category STRIDE matrix and calls us.amazon.nova-lite-v1:0 via the Bedrock Converse API (1,104.0 ms median across 8 benchmarked calls, 595 mean tokens). SQLiteAuditLedger chains every event digest from GENESIS_SECPOSTURE_SQLITE_0000 and verifies 58 rows in 1.792 ms.
04 · Trade-Offs

Trade-Offs

SecPosture makes deliberate engineering trade-offs between static precision, diff size, LLM latency, and serverless isolation.

Design Decisions
01 · STATIC AST VS DYNAMIC CALLS

Fast Deterministic Call Graphs vs. Dynamic Reflection

Building call graphs statically with Python ast finishes in 0.509 ms median without executing untrusted service code, at the trade-off that targets invoked only via dynamic getattr() or runtime plugin registries cannot be resolved statically without runtime trace edges.

02 · SURGICAL DIFFS VS DEAD-CODE CLEANUP

Patching Only Reachable Functions Keeps Code Reviews Small

autopatch_loop.py intentionally patches only functions reachable from active entrypoints (12 to 25 changed lines per service) and leaves dead-code helpers untouched. That minimizes merge risk for urgent security hotfixes while tracking dead-code removal separately as non-blocking backlog hygiene.

03 · DETERMINISTIC GATES VS MODEL FLEXIBILITY

Mandatory /tmp Unittest Verification Adds ~65 ms Per Patch

Spawning an isolated subprocess.run(..., shell=False) test runner in /tmp adds 64.63 ms median compared to returning an unverified text diff immediately. That 65 ms budget guarantees syntax validity, 0 remaining reachable vulnerabilities, and 100% passing unit tests before a builder ever opens a pull request.

04 · GROUNDED BEDROCK REVIEWS

Sub-Millisecond Graph Solvers Paired With On-Demand Nova Lite

Running Amazon Bedrock on every commit line would be slow and costly. SecPosture runs AST reachability (0.509 ms), IAM pathfinding (0.021 ms), and CloudTrail correlation (0.006 ms) deterministically first, invoking us.amazon.nova-lite-v1:0 (1,104 ms median) only for human-readable launch reviews and pull-request summaries.
